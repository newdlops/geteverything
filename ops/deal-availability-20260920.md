# 게시글 종료·삭제 상태 저장

기존 `deals.is_end`를 실제 원문 상태에 맞춰 갱신한다. 기존 API의 `is_end` 필드는 그대로 사용하므로 웹 서버나 클라이언트 배포 없이 DB 상태를 읽을 수 있다. 원문이 없어져도 게시글 레코드·고유 상품 연결·가격 이력·이미지 기록은 삭제하지 않는다.

## 판정 기준

| 원문 관찰 | 저장 동작 |
| --- | --- |
| 아카라이브 본문 헤더의 `close-deal`, FMKOREA 본문의 종료 배너 | `ended`, `is_end=True` |
| 원문 제목의 독립된 `[종료]`, `(품절)` 등 명시적 표시 | `ended`, `is_end=True` |
| 사이트 오류 영역의 명시적 게시글 없음 안내 또는 HTTP 410 | `deleted`, `is_end=True` |
| HTTP 404 최초 관찰 | 확인 대기, 기존 `is_end` 보존 |
| 최소 15분 간격의 연속 404 두 번 | `deleted`, `is_end=True` |
| 403·429·430·5xx, 타임아웃, 로그인·보안 페이지, 목록으로의 이동, 인식할 수 없는 HTML | 미확인 결과만 저장, 기존 확정 상태 보존 |
| 정상 상세 페이지가 다시 확인됨 | `active`, `is_end=False` |

목록에서 보이지 않는다는 이유나 게시글 나이만으로 종료시키지 않는다. 댓글과 다른 게시글의 종료 배지는 판정에 사용하지 않는다. `품절가능성`, `품절풀림`, `마감임박` 같은 제목은 종료로 판정하지 않는다. 판매처의 실제 재고까지 조회하는 기능은 아니며, 커뮤니티 원문의 명시적 상태가 기준이다.

`deal_availability`는 게시글당 한 행으로 현재 상태, 마지막 관찰 결과·근거, 확인 시각, 종료 감지 시각, 404 확인 횟수·시작 시각, 다음 확인 시각을 보관한다. `ended_at`은 실제 판매 종료 시각이 아니라 크롤러가 감지한 시각이다. 시간상 오래된 관찰은 최신 상태를 덮어쓰지 않는다. 상태만 확인할 때는 가격·썸네일·게시글 `update_at`을 갱신하지 않는다.

## 수집과 자원 제한

5개 사이트의 기존 상세 수집에서 받은 HTML을 재사용한다. 추가 브라우저나 별도 워커를 띄우지 않는다. 원문이 삭제돼 상세 파서가 가격·날짜를 읽지 못해도, 상태 저장은 정상 상품 파싱과 독립적으로 처리한다. 상태만 처리한 응답은 일반 수집 성공 건수에 포함하지 않아 뽐뿌의 빈 수집 감지를 유지한다.

정상 수집과 별도로 사이트별 회차당 최대 5개의 기존 글을 낮은 요청 우선순위로 확인한다. `CRAWLER_STATUS_RECHECK_LIMIT=0`이면 이 추가 확인을 끌 수 있다. 값을 높여도 상한은 5다. 뽐뿌의 프록시와 아카라이브의 브라우저 세션·인증 쿠키도 기존 경로를 사용한다.

- 일반 재확인은 최근 12시간 동안 수집되지 않은 글 중에서 선정한다. 미확인 글이 반복 확인된 새 글에 밀리지 않게 순환한다.
- 404 확인 대기 글은 30분 후부터 우선 재확인한다. 실제 시각에는 해당 사이트의 회차와 큐 대기가 추가된다.
- 정상 글은 12시간, 확정 종료·삭제는 72시간, 미확인·접속 실패는 2시간 후 재확인 대상으로 돌아온다.
- 전체 과거 게시글을 즉시 전수 검사하지 않는다. 원문에 종료 표시가 없거나 접근 차단이 계속되면 종료 여부를 확정할 수 없다.

FMKOREA의 목록 링크에서는 숫자 문서 번호를 추출하고, 운영에서 동작하는 게시판 진입 경로 `/?mid=hotdeal&...&document_srl=<번호>&listStyle=webzine&cpage=1`로 상세 요청을 보낸다. 과거 글 재확인에도 같은 경로를 쓴다. 원래 링크 `index.php?...`를 직접 여는 경우 보안 페이지가 반환되는 것을 서버에서 확인했고, 게시판 경로의 정상 상세 응답도 실제 Chrome으로 검증했다. 저장된 게시글 ID와 원문 URL은 유지한다.

## 배포·검증

2026-09-20 12:56 KST에 `168.107.29.18`에 반영했다. 새 테이블을 추가하는 `0014_deal_availability` 마이그레이션을 먼저 적용하고 크롤러를 교체했다. 이후 FMKOREA 브라우저의 출력 대기 문제를 발견해 13:14 KST에 브라우저 실행 처리를 보완했고, 13:40 KST에 정상 상세 주소 경로를 반영했다. CPU·메모리·로그·네트워크 설정은 보존했고, 웹·상품 워커·모델·FlareSolverr는 교체하지 않았다. 세 차례의 제어된 재시작 구간은 각각 1.77초, 1.32초, 2.38초였다.

- 최종 이미지: `crawler-image:availability-20260920-r3` / `sha256:9cac4ad5c9cdf92d01cfaec4aba8258f7b009ab26357bf35c89a22b7530884c0`
- 로컬과 새 운영 이미지에서 관련 테스트 58개 통과. SQLite에서 실제 상태 저장 SQL, 404 재확인, 종료 후 복구, 기존 가격·이미지 보존을 검증했다.
- 로그를 읽지 않는 부모 프로세스에 브라우저가 대량 출력해도 종료할 수 있는 회귀 시험을 추가했다. 운영과 같은 ARM 이미지에서 실제 Chrome을 띄워 HTML을 읽고, 네이티브 표준 출력·오류가 `/dev/null`로 연결된 것도 확인했다.
- 실제 공개 페이지 표본 9개에서 진행·종료 판정을 확인했다. 아카라이브·FMKOREA·쿨엔조이의 종료 글과 5개 사이트의 정상 글을 포함한다. 별도로 뽐뿌·쿨엔조이의 삭제 안내 HTML과 차단·404 응답도 확인했다.
- `makemigrations --check --dry-run`으로 로컬 모델과 마이그레이션 일치를 확인했다.

13:45 KST 최종 확인에서는 종료 25건, 삭제 10건이 저장돼 있었다. 확정 상태와 `is_end`의 불일치는 0건이다. 최종 배포 후 5분 동안 5개 사이트 모두 DB 갱신을 확인했으며, 과거 글 15개도 별도 재확인했다. 다음 수치는 해당 확인 시점의 누적 상태이며 전체 과거 글의 검사 완료를 뜻하지 않는다.

| --- | ---: | ---: | ---: |
| ARCA | 5 | 11 | 0 |
| EOMISAE | 20 | 0 | 0 |
| FMKOREA | 80 | 12 | 0 |
| PPOMPPU | 80 | 0 | 8 |
| coolnjoy | 80 | 2 | 2 |

운영 파일 해시는 배포 기록과 일치했다. 크롤러의 자동 재시작과 OOM은 없었고, 기존 다른 컨테이너의 시작 시각도 유지됐다. 배포 후 5분 CPU 평균은 62.28%였으며, 이는 장기 부하 개선 비교가 아닌 배포 직후 관찰값이다. 상세 기록은 [deal-availability-20260920.json](deal-availability-20260920.json)에 있다.

뽐뿌에서는 판매처 표기가 없는 일부 목록 행에서 기존 `shop_name` 파싱 오류가 계속 관찰됐다. 이번 상태 저장과 별개인 기존 수집 제한으로 남겨 둔다. FMKOREA의 이전 보안 페이지 응답 94건은 미확인 상태로 유지했으며, 정상 재수집되면 갱신한다. 두 사이트의 접속 실패나 파싱 실패를 삭제로 간주하지 않는다.

FMKOREA 정지 당시 Chrome의 주 스레드는 `anon_pipe_write`에, 크롤러는 응답 대기에 머물렀다. 사용 중인 undetected-chromedriver가 Chrome의 출력 두 개를 읽지 않는 파이프로 연결하는 구현도 확인했다. Linux에서는 임시 실행 스크립트가 같은 PID로 Chrome을 실행하면서 네이티브 출력만 버리도록 했다. 애플리케이션의 수집·상태·오류 로그는 기존 Docker 로그에 남는다. 실행 스크립트는 브라우저 종료 시 정리한다.

```bash
python -m django test \
  crawlers.tests.unit.test_availability \
  crawlers.tests.unit.test_pipelines \
  crawlers.tests.unit.test_recovery_parsing \
  crawlers.tests.unit.test_flare_resources \
  crawlers.tests.unit.test_selenium_resources \
  crawlers.tests.unit.test_run_queue \
  crawlers.tests.unit.test_ppomppu_proxy \
  --settings=crawlers.tests.settings --noinput
```

크롤러 이미지는 웹 로그인용 패키지를 포함하지 않으므로 마이그레이션에 `--skip-checks`를 사용해 웹 URL 검사를 생략한다. DB 마이그레이션과 의존성 검사는 그대로 수행한다. 첫 배포 시 URL 검사에서 중단됐으나, 기존 크롤러를 정지하기 전 단계여서 기존 수집에는 영향이 없었다.

최종 보완 이미지의 첫 빌드는 누적된 Docker 계층 상한으로 중단됐다. 수정 파일을 한 계층에 복사하도록 빌드 구성을 바꿔 해결했다. 테스트와 마이그레이션이 통과하기 전에는 기존 크롤러를 정지하지 않았다.

서버 `/root/crawler-availability-20260920/`, `/root/crawler-availability-20260920-r2/`, `/root/crawler-availability-20260920-r3/`에 배포 기록·테스트·마이그레이션·검증 결과와 비공개 Docker 설정 백업을 보관했다. 기능 적용 전 컨테이너는 `crawlers-bot-before-availability-20260920`이며, 각 보완 직전 컨테이너는 같은 이름에 `-r2`, `-r3`가 붙어 있다. 기능 전체를 복구할 때는 현재 크롤러를 정지한 뒤 기능 적용 전 컨테이너를 원래 이름으로 바꿔 시작하고 `crawler-image:latest` 태그를 이전 이미지 `ad92e3baafe1…`로 돌린다. 새 상태 테이블과 판정 데이터는 유지할 수 있다.
