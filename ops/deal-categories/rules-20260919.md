# 2026-09-19 미분류 1% 이하 작업

## 변경 내용

`2026-09-19-v2/rules-4`는 제목의 상품명·모델명 규칙을 보완하고, 제목만으로 판단하기 어려운 경우 제한된 판매처 정보와 원본 게시판 카테고리를 보조 근거로 사용한다. 외부 추론 API는 사용하지 않는다.

- 상품명과 주상품·사은품 관계를 우선한다. 실제 여러 상품군이 섞인 구성은 미분류로 남긴다.
- 판매처 URL은 정확한 호스트 이름만 확인하며 분류 과정에서 네트워크 요청을 하지 않는다. 닮은 도메인은 인정하지 않는다.
- `먹거리`, `PC/하드웨어` 등 명확한 게시판은 대분류의 보조 근거로 사용한다. `기타`, `가전/가구`, `전자제품` 등 혼합 범주는 이 방식에서 제외한다. 원본 게시판도 잘못 지정될 수 있으므로 제목의 상품 근거가 우선한다.
- 자동차·차량용품, 도서·문화 대분류를 추가했다. 할인쿠폰·포인트·응모·쇼핑행사·멤버십 등은 상품권·혜택·서비스 아래에서 구분한다. 기존 카테고리 코드는 유지한다.
- 광고 자리표시자, 상품 정보가 없는 제목, 판단할 수 없는 혼합 구성은 분모에서 제외하지 않고 미분류로 센다. 임의의 기본 분류로 채우지 않는다.
- 어드민에서 제목·판매처·게시판 중 어떤 근거로 분류했는지 확인할 수 있다.

새 규칙은 `context.py`, 상품 사전은 `vocabulary.py`, 주상품 및 문자열 충돌 처리는 `rules.py`에 있다. 분류표는 `taxonomy.py`에 정의한다.

## 수집과 동시 처리

마이그레이션 `0011_classification_context`는 제목 외에 사이트·원본 카테고리·판매처·상품 링크 변경도 재분류 요청으로 기록한다. 가격이나 조회수만 바뀌면 재분류하지 않는다. 캐시 키에는 제목과 실제 분류에 사용한 모든 문맥 정보가 포함된다.

수동 지정은 자동 수집·업그레이드·지연된 모델 결과보다 우선한다. 요청 revision과 입력 제목이 달라진 과거 작업 결과는 저장하지 않는다. 과거 글 재처리는 분류 행만 잠그고 원본 게시물 행은 잠그지 않아 크롤러의 잠금 순서와 충돌하지 않게 했다.

일회성 재처리는 0.1 CPU·192 MiB, 25건 배치·0.15초 휴식·최대 15분으로 실행한다. 일반 분류·수치 워커는 0.15 CPU·192 MiB 제한을 유지한다. 처리 도중 건너뛴 행은 일반 워커의 업그레이드 큐가 이어서 처리한다. 크롤러와 썸네일 워커는 별도 서비스다.

로컬 LLM은 검토 후보만 제안한다. `CATEGORY_LLM_AUTO_PUBLISH=0`, `CATEGORY_LLM_BACKFILL=0` 정책을 유지한다.

```sql
SELECT count(*) AS total,
       count(*) FILTER (
           WHERE c.deal_id IS NULL OR c.status <> 'ready' OR c.category = ''
       ) AS unclassified,
       round(100.0 * count(*) FILTER (
           WHERE c.deal_id IS NULL OR c.status <> 'ready' OR c.category = ''

FROM deals d
LEFT JOIN deal_classifications c ON c.deal_id = d.id;
```
