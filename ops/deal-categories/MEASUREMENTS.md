# 수량·단가 정규화 설계

카테고리 보완과 함께 상품 제목의 중량, 용량, 묶음 수량, 가격을 정리한다. 카테고리를 수동으로 고정해도 가격·수량 갱신은 계속된다. 외부 추론 API는 사용하지 않으며 수치 계산은 Decimal과 명시적인 문법으로 처리한다.

## 저장과 작업

- `deals.numeric_evidence`: 수집 페이지의 가격·배송비 원문. 기존 가격 정수 필드는 API 호환성을 위해 보존한다. 원문이 없는 기존 외화 가격의 유실된 소수점은 복원했다고 간주하지 않는다.
- `deal_measurements`: 입력 스냅샷, 계산 결과 JSON, 버전, 상태, 재시도·작업 임대. 제목·가격·통화·배송비·원문 가격 변경을 DB 트리거가 감지한다.
- 별도 분류 워커가 신규 글 우선으로 수치도 처리한다. 역사 데이터는 저장한 커서로 백필한다. revision 확인으로 이전 입력의 결과가 최신 가격을 덮어쓰지 않게 한다.
- 기본 단위: 중량 g, 용량 ml, 개수는 캔·개·정·매 등 원래 단위. 단가는 100g, 100ml, 개당을 각각 제공한다.
- 상품 가격과 배송비 포함 가격을 분리한다. 기존 배송비 0만으로 무료라고 판단하지 않는다. 제목의 선택지·범위·혼합 구성·성분 함량·제품 용량·가격 조건이 모호하면 해당 계산을 보류하고 이유를 남긴다.

## 환율

사용자가 공식 일별 비교 환율의 자동 갱신을 선택했다. ECB 공식 일별 XML의 EUR 기준 환율로 `KRW/EUR ÷ 원통화/EUR`를 계산한다. JPY도 100엔이 아닌 1엔 기준이다. 출처·기준일·수집 시각을 DB에 보존한다. 제목 등 상품 데이터는 환율 요청에 보내지 않는다.

네트워크 실패 시 마지막 정상 값을 보존한다. 7일을 넘은 환율로 새 환산 금액을 보여주지 않는다. 기준환율은 상품 비교용이며 카드 수수료·관세·실제 청구 환율은 포함하지 않는다. 원화 환산은 조회 시 현재 환율 스냅샷을 적용해 기존 모든 상품을 다시 쓰지 않아도 갱신된다.

공식 설명: https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html

## 어드민과 API

기존 Django 어드민의 표·필터·읽기 전용 상세 화면을 유지한다. 분류 상세에서 수량·단가 상세로 연결하고, 상품 수량·단가 목록에서 제목, 처리 상태, 총량, 단가를 확인한다. 상세에는 원문 근거, 배송비 포함 여부, 환율 날짜와 계산 보류 이유를 표시한다. 긴 제목과 계산식을 줄바꿈하고 작은 화면의 표는 가로 스크롤한다.

API는 기존 필드에 `measurements`와 `measurement_status`를 추가한다. 금액은 소수 정밀도를 유지하는 문자열, 알 수 없는 값은 null이다. 대기·오류 상태에서 오래된 결과를 정상 값처럼 노출하지 않는다.

## 통과 기준

- 500ml × 24개 = 12,000ml; 12,000원일 때 100ml당 100원.
- 200g × 5팩 = 1,000g; 40매 × 16팩 = 640매; 중첩 묶음에서 배수를 중복 적용하지 않는다.
- SSD 2TB, 비타민 1000mg의 성분 함량, 4~5개 범위는 무게·확정 개수로 오인하지 않는다.
- 제목 끝의 24캔을 24원으로 읽지 않으며, 수집 가격 $19.99의 소수점을 보존한다.
- 새 가격 요청·수동 카테고리·배송비 미상·오래된 환율·지원하지 않는 통화가 각각 독립적으로 처리된다.
- DB 트리거·원자성, 실제 수집·백필, API와 390/768/1440px 어드민을 기능과 화면으로 따로 검증한다.

## 구현과 운영

핵심 코드는 `gadmin/metrics/`에 있고, 저장 모델과 트리거는 `deals.0010_deal_measurements`로 추가한다. 분류 워커의 기존 0.15 CPU·192 MiB 제한을 유지하면서 수치 작업을 함께 처리한다. 모델 추론과 환율 다운로드는 별도 스레드에서 실행해 규칙·산술 계산을 막지 않는다. 분류를 수동 지정한 글도 수치 분석은 계속된다.

실제 배포 이미지, 백필 완료 수치와 검증 결과는 [2026-09-18 운영 기록](measurements-20260918.md)에 정리했다.

`python -m gadmin.categories.worker --status`에서 `measurements`, `measurements_backfill`, `rule_upgrade`를 함께 확인한다. `classification_state`의 `fx:worker`에는 환율 갱신 상태, `fx:ECB:latest`에는 최근 정상 스냅샷, `fx:ECB:YYYY-MM-DD`에는 해당 날짜의 환율을 보관한다. 정상 수집 후 6시간, 실패 후 1시간 간격으로 다시 확인한다. 웹 조회 캐시는 최대 5분이다.

수치 백필은 15초마다 최대 100건씩 등록하고 신규 요청을 우선한다. 수정한 `rules-2`도 이전 자동 분류를 최대 100건씩 재처리하며 수동 지정은 건드리지 않는다. `review` 건수를 줄이기 위한 규칙 추가와 실제 정확도 개선은 별개의 검증 대상이다. 기존 500건 회귀 표본에서는 422건을 분류했고, 해당 검토 라벨과 일치했다. 이 표본은 규칙 개선에 사용했으므로 독립적인 정확도 수치가 아니다.

가격 수집에서 확인한 오류도 수정했다. FMKOREA의 구조화된 가격 필드를 사용하고, 제목 끝의 `24캔`을 `24원`으로 읽는 기존 대체 규칙을 제거했다. `3,000원` 배송비도 전체 숫자로 읽는다. 수집 원문의 `$19.99`는 JSON 문자열로 보존해 기존 정수 필드와 별도로 계산한다. 이미 정수로만 남은 외화 가격에는 소수점 원문이 없다는 설명을 붙인다. 가격 근거가 불분명한 과거 값은 단가 계산에서 제외한다.

화면은 **상품 수량·단가** 목록과 읽기 전용 상세로 제공한다. 분류 상세의 **수량·단가 상세 보기**에서 이동할 수 있다. 작은 화면의 목록은 기존 Django 어드민처럼 가로 스크롤하며, 상세는 한 열로 표시한다. `ready`는 단가를 계산할 수 있다는 뜻이고, `partial`은 확인한 정보만 제공, `review`는 범위·혼합 구성 등 계산을 보류할 사유가 있다는 뜻이다. 가격을 모르면 0원으로 표시하지 않는다.

환율 계산은 전체 원화 금액을 먼저 계산한 뒤 총량으로 나눈다. 먼저 반올림한 외화 단가에 환율을 곱하지 않아 이중 반올림을 방지한다. 상품 가격 단가와 배송비 포함 단가 모두 같은 방식이다. 양이 섞인 세트, 중량이 낱개인지 포장 전체인지 불명확한 경우는 해당 총중량을 계산하지 않는다. 성분 함량과 종이 평량도 총중량에서 제외한다.

`measurements-2`에서는 용기·기기의 표시 용량을 `capacity_ml`로 분리한다. 텀블러 600ml는 내용물 600ml로 취급하지 않으며 100ml당 가격을 만들지 않는다. 개수가 명시되어 있으면 개당 가격은 제공한다. 이전 결과 중 이 변경에 해당하는 행만 재계산한다.
