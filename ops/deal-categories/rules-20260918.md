# 2026-09-18 미분류 감소 작업

## 원인과 변경

21:29 KST 운영 스냅샷의 43,406건 중 19,494건(44.9%)이 미분류였다. 사전에 없는 상품명 18,741건, 상품 규칙 충돌 563건, 로컬 모델의 검토 후보 163건 등이었다. 물티슈·구운란·감귤·참기름 같은 일반 상품도 누락됐다.

`rules-3.1`은 기존 규칙이 해결하지 못한 제목에 상품 어휘와 모델명 규칙을 적용한다. 상품명이 없고 브랜드만 명확한 경우에는 기존 분류표의 대분류를 사용한다. 삼성·LG처럼 여러 상품군을 만드는 제조사, 커뮤니티명, 용량이나 가격만으로 분류하지 않는다. 원본 사이트의 카테고리는 정답으로 사용하지 않는다.

- 식품·위생용품·의류·화장품·PC 모델명 등의 누락을 보완했다.
- 팬티형 기저귀, 김치냉장고, 세탁기용 세제, 프로틴 초콜릿맛, 모니터링 이어폰, 식당 금액권의 상품 관계를 구분한다.
- 룰루레몬의 레몬, 메탈슬러그의 러그, 크린스틱의 린스, 콜라보·콜라겐의 콜라를 다른 상품으로 오인하지 않게 했다.
- `U+`, `SE+`, `1+1`을 독립 상품 목록으로 나누지 않는다. 공백으로 구분된 서로 다른 상품 묶음은 검토 상태로 남긴다. 주상품을 모르는 구성에서 부속 수저세트만 보고 주방용품으로 분류하지 않는다.
- 외부 추론 API는 사용하지 않는다. 로컬 LLM은 검토 후보만 남기는 정책을 유지한다.

## 검증

분류·수치 테스트 50개를 통과했다. 수동 지정 보호, 신규 수집 작업 우선, 오래된 추론 결과의 덮어쓰기 방지, 배치 제한, 이전 LLM 검토 결과의 규칙 재처리를 포함한다.

기존 500개 제목 검증에서는 447건을 분류했고 대분류가 검토 라벨과 일치했다. 이 라벨은 코딩 어시스턴트가 검토했으며 규칙 개발에도 사용했다. 독립적인 운영 정확도나 사람 인증 정답을 뜻하지 않는다. 추가로 새 분류 결과 표본과 기존 분류가 달라지는 사례를 검토해 부분 문자열·부속품·브랜드의 `+` 문제를 보완했다.

동일한 43,406개 게시물의 운영 DB 비교(21:29 → 22:37 KST):

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 분류 있음 | 23,912 | 34,806 |
| 미분류 | 19,494 | 8,600 |
| 분류율 | 55.1% | 80.2% |

새로 분류된 것은 10,956건이고, 근거 부족·혼합 구성 등으로 검토 상태로 돌린 것은 62건이다. 미분류 순감소는 10,894건(55.9%)이다. 두 스냅샷 사이에 해당 게시물의 삭제·제목 변경은 없었으며 전부 최종 `rules-3.1`로 처리됐다. 사전 오프라인 계산과 운영 DB 결과가 일치했다. 로컬 계산은 약 2.44초였으며 운영 서버의 처리 시간이나 정확도로 해석하면 안 된다.

## 운영 적용과 재처리

분류 워커만 변경했고 크롤러·웹·썸네일 워커는 재시작하지 않았다. 최종 분류 워커 이미지는 `1b4755669408`이며 적용 기록은 크롤러 서버의 `/root/category-rules31-20260918/deployment.json`에 있다. 이전 워커 설정은 `/root/category-worker-backups/1789737358809253892/runtime.json`에 보관했다. 이 설정은 비밀값이 포함될 수 있으므로 공개하지 않는다.

기존 글은 `python -m gadmin.categories.upgrade`로 처리한다. 운영 일회성 컨테이너 `geteverything-category-upgrade-r31`은 0.1 CPU·192 MiB로 실행했다. 처음에는 100건·0.2초 휴식을 사용했으나 DB 잠금 대기로 일반 워커가 한 번 자동 재시작했다. 이후 일회성 작업만 25건·0.1초 휴식으로 다시 실행해 잠금 시간을 줄였다. 일반 워커의 0.15 CPU·192 MiB 제한은 유지했다. **0.1 CPU 환경에서는 `--batch-size=25 --pause=.1`을 지정한다.**

22:37 KST 최종 관측:

- 일회성 작업은 22:30 KST에 정상 종료했다. 25건 설정으로 남은 1,680건을 약 36초에 처리했고, 종료 코드 0·OOM 없음이었다. 완료한 행은 중복 처리하지 않았다.
- 기존 글 전부와 신규 수집분을 포함한 43,428건이 최종 규칙 버전이었다. 분류 완료 34,819건, 검토 8,605건, 신규 글의 로컬 모델 대기 4건이다. 규칙 처리 대기와 오류는 0건이었다.
- 이전 규칙이 남은 행이 없고 재분류 대기열도 비었다. 상태 레코드의 `phase=queued`는 등록 종료를 뜻하며, 실제 대기 건수·버전도 함께 확인했다.
- 크롤러는 19:08 KST의 시작 시각을 유지했고 재시작 0·OOM 없음이었다. 5개 커뮤니티의 최근 수집 갱신을 확인했다.
- 일반 워커는 자동 복구 후 22:16 KST부터 계속 실행 중이었다. 최종 서비스 `NRestarts=1`, 컨테이너 OOM 없음이었으며, 이후 추가 재시작은 없었다.
- 수치 처리 결과 43,428건도 유지됐고 대기·오류가 없었다.
- 운영 API에서 물티슈(91886), 구운란(94973), 삼성 9100 PRO(103369), 룰루레몬(96263), 메탈슬러그(119203), U+ 요금제(117427), 태블릿용 터치펜(108329)의 카테고리를 확인했다.

작업 중 보완한 이전 일회성 컨테이너는 정지 상태로 보존했다. 최종 배치 설정과 이전 진행 로그는 `/root/category-rules31-20260918/small-batch.json`에 있다. 새 모델 정책이나 추가 외부 API는 도입하지 않았다.

재처리는 행 잠금 안에서 현재 입력을 읽고 `request_revision`을 증가시킨다. 수동 지정과 신규 수집 대기 작업을 제외하며 원본 게시물·가격·수치 결과를 변경하지 않는다. 충돌로 건너뛴 행은 기존의 작은 배치 업그레이드가 이어서 처리한다. 명령은 최대 50,000건·15분으로 제한하며 재실행해도 이미 현재 버전인 행은 다시 쓰지 않는다.
