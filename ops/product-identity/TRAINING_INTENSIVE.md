# 상품 고유성 LLM 학습 강화

2026-09-20, 크롤러 서버 `168.107.29.18`에 적용하는 학습 구성이다. 외부 AI API 없이 기존 Qwen3.5 2B의 LoRA 가중치를 실제로 갱신한다. 상품번호 수집·규칙 연결·별도의 가벼운 매칭 모델과 구분한다.

## 이전 결과와 변경 이유

이전 전체 학습은 실제 92 step을 수행했지만 검증 10건 중 정답이 1건에서 2건으로 늘어나는 데 그쳤다. 혼합 상품을 단품으로 보는 오류도 1건 남아 운영 반영에서 탈락했다. 검증 손실 감소만으로 상품 연결 품질을 판단하지 않는다.

새 예제는 제목에 없는 브랜드 번역, 용량·수량의 모델번호 오인, 상품명 세대 누락, 혼합·선택 구성의 단품 오인을 다룬다. 제목 필드를 검토한 예제와 판매처·가격·묶음 수 변형을 합쳐 308건이다. 자동 연결 결과나 모델 추측을 정답으로 넣지 않는다. 구성 예제의 성적은 실제 서비스 정확도가 아니다.

| 항목 | 이전 | 변경 |
|---|---|---|
| 학습 / 검증 | 46 / 10 | 246 / 62 |
| 검증 범위 | 6개 상품군 | 21개 상품군, 연결 거부 10건 |
| 마지막 블록 LoRA | Q/V, rank 8 / 69,632개 | Q/K/V/O + gate/up/down, rank 16 / 638,976개 |
| 최대 학습 | 2 epoch, 92 step | 4 epoch, 984 step (설정 한도 1,200) |
| 학습률 | 고정 0.0002 | 최대 0.00008, warmup 후 cosine 감소 |
| 체크포인트 | 마지막 결과 | 매 epoch 비교 후 검증 손실 최저 결과 |
| CPU / 메모리 한도 | 0.20 CPU / 6 GiB | 0.35 CPU / 6 GiB |

상품군·정규화 제목 별칭은 학습과 검증 중 한쪽에만 속한다. 이전 검증 상품군도 유지한다. 같은 상품의 묶음 차이는 연결하고 용량·맛·모델 차이는 구분하는지, 검증 결과를 쌍으로도 비교한다.

## 실행과 자원 보호

`geteverything-product-training.service`가 데이터 내보내기 → 고정 계층 캐시 → 가중치 학습 → GGUF 변환 → 62건씩 기존/후보 생성 평가 → 반영 여부 판단을 수행한다. `probe.py`는 2 step 가중치 변경과 변환·추론 호환성만 확인하며 운영 반영을 하지 않는다.

고정 계층의 출력은 모델 revision과 입력 토큰으로 식별해 재사용한다. 캐시 생성 전 디스크 3 GiB 여유를 확인하며 새 실행에는 5 GiB가 필요하다. 완료한 최근 두 실행과 활성 어댑터를 보존한다. 다른 실행이 참조하지 않는 캐시는 7일 또는 4 GiB 정리 기준을 적용한다.

호스트 CPU가 80% 이상으로 연속 2회 관측되면 학습을 일시정지하고 65% 미만이면 재개한다. 가용 메모리 3 GiB 미만이면 중지하고 체크포인트를 보존한다. 학습 중 일반 로컬 LLM 추론은 자원을 양보하며 크롤러·규칙 연결·가격 기록은 계속 돈다. 학습 18시간, 생성 평가 4시간, 서비스 전체 24시간 제한이다. 컨테이너 로그는 각 2 MiB × 2개로 제한한다.

매일 02:30 KST에 새 정답과 학습 설정을 확인한다. 같은 완료 작업은 반복하지 않으며 같은 데이터·설정의 실패는 최대 3회까지만 재시도한다. 새 운영자 정답 16건 또는 검토 예제·학습 설정 변경 시 다시 학습할 수 있다.

## 반영 조건

- 검증 40건 이상, 12개 상품군 이상, 연결 거부 예제 8건 이상.
- 가중치 실제 변경, 검증 손실 개선, 기존 모델보다 정답 증가, 정답률 80% 이상.
- 기존 정답 회귀 0건, 혼합 상품의 단품 오인 0건, 다른 상품의 병합 0건.
- 같은 상품의 분리 오류 증가 없음, 모든 출력의 구조·제목 근거 유효, 응답 지연 기준 통과.
- 실행 중 학습 프롬프트 버전이 바뀌지 않았는지 확인 후 상품 추출 요청에만 어댑터 적용.

`status.json`의 `caching_frozen_layers`는 전처리다. `training`의 `step`이 증가해야 실제 가중치 학습이 진행 중이다. `probe_complete`는 짧은 시험 완료이고 `promoted`/`active.json`이 전체 평가를 통과한 운영 반영 여부다. 상태는 어드민의 기존 로컬 LLM 미세학습 화면에도 게시된다.

## 검증 기록

로컬 상품·썸네일 테스트 121개, 새 운영 워커의 테스트 62개, 서버의 학습·평가·CPU 연산 테스트 8개가 통과했다. 전체 308건의 최대 토큰 수는 340으로 768 제한 이내다.

2026-09-20 17:20 KST에 2 step 기술 시험을 마쳤다. 학습 대상 638,976개의 설정을 확인했고, LoRA B 가중치 제곱합 `0.0061011544`로 실제 갱신을 확인했다. 최저 검증 손실 체크포인트를 GGUF로 변환해 llama.cpp가 로딩하고 JSON을 생성하는 것까지 확인했다. 시험 응답에는 SSD를 electronics로 분류하고 용량을 variant로 넣는 오류가 남아 있으므로 품질 통과나 운영 반영으로 해석하면 안 된다. `active.json`은 없다.

시험에서 고정 계층 캐시는 건당 약 79~81초, 마지막 학습 step은 14.76초였다. 17:21 KST에 전체 학습 작업을 시작했다. 전처리·학습·생성 평가를 합쳐 약 14~18시간 예상이며 자원 보호 중지와 제목 길이에 따라 달라진다. 일반 LLM 추론은 학습에 자원을 양보한다. 학습 작업 중 FMKOREA·ARCA·PPOMPPU 신규 게시물의 DB 저장과 상품번호 참조 증가를 확인했다. 크롤러와 FlareSolverr는 재시작되지 않았다.

서버 백업과 배포 기록은 `/root/product-training-20260920-intensive`에 있다. [배포·시험·전체 작업 시작 기록](training-intensive-20260920.json)에 이미지, 코드 해시, 실측 값과 시작 시점 상태를 보관한다. 이 기록은 전체 학습 완료 결과가 아니며, 최신 상태는 어드민 또는 서버 상태 파일에서 확인한다.
