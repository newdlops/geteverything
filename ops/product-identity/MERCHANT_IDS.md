# 제목과 쇼핑몰 상품번호를 함께 사용하는 상품 연결

제목의 브랜드·모델·개별 용량·맛·옵션에 쇼핑몰 상품번호를 보조 근거로 더한다. 하나의 상품 UUID에 여러 커뮤니티 게시물과 여러 쇼핑몰 번호가 연결된다. 묶음 개수는 기존처럼 단가 계산에 사용한다.

## 저장과 연결

- `product_sources`: 게시물별 제목·쇼핑몰 링크 2개, 요청 revision, 처리 상태·시각·재시도 횟수. 신규 글과 제목·링크 변경을 트리거가 같은 트랜잭션에서 기록한다. 조회수나 같은 링크의 반복 저장은 재처리하지 않는다.
- `product_references`: 쇼핑몰·상점 범위·상품/옵션 번호, 정규 URL, 추출 경로. 조회 키를 인덱싱하며 다른 쇼핑몰에서 우연히 같은 숫자를 사용해도 충돌하지 않는다. 원본 쇼핑몰 링크는 보존한다.
- 동일 번호의 기존 상품 연결을 찾고 새 제목에 상품명·브랜드·모델·옵션 근거가 있는지 확인한다. 용량·맛·색상·부속품 등이 충돌하거나 후보 UUID가 여러 개면 번호만으로 연결하지 않는다. 구체적인 옵션 번호가 있으면 상위 상품번호보다 우선한다.
- 연결 시 `DealProduct.source=identifier`, `extraction.shop_evidence`에 사용한 번호·참조 게시물·revision을 기록한다. 연결 요청 revision을 올려 먼저 시작한 모델의 늦은 응답이 덮어쓰지 못하게 한다. 수동 연결은 보존하고, 대기하던 과거 글은 새로운 참조가 생기면 재확인한다. 이미 확정된 별도 UUID를 일괄 병합하는 기능은 아니다.
- 수집만으로 가격 관측을 새로 만들지 않는다. 현재 제목의 `identity_revision`에 속한 관측만 연결하고 과거 다른 제목의 가격은 보존한다. 자동 번호 연결을 운영자 확정 학습 정답으로 만들지 않는다. 외부 AI API는 사용하지 않는다.

네이버 브랜드/스마트스토어, 쿠팡, G마켓, 옥션, 11번가, 롯데온, 카카오쇼핑, 오늘의집, 알리익스프레스, Amazon, SSG, 무신사와 명시적인 Cafe24 상품 URL 형식을 지원한다. 상품 목록·검색·기획전 페이지는 상품번호로 사용하지 않는다. 쿠팡 상품/옵션 단위 구분은 [공식 설명](https://developers-v1.coupangcorp.com/hc/en-us/articles/360033917473-Coupang-OPEN-API)을 참고했다.

뽐뿌·FMKOREA·unsafelink·LinkPrice 중계 링크의 URL/퍼센트/Base64 인코딩은 서버 내부에서 해제한다. 번호가 드러나면 외부 요청은 없다. 허용된 짧은 주소는 1분당 최대 1건, 작업당 전체 8초, 입력당 최대 3회만 확인한다. 상품번호가 나온 목적지에 도달하면 본문을 받지 않는다. 기존 공개 IP 검증·DNS 고정·리다이렉트 제한을 재사용하며 성공 결과는 24시간 캐시한다.

규칙 버전은 `products-6`이다. `블루투스`를 `블루` 색상으로 읽던 오탐과 `3kg세트`처럼 단위 뒤에 붙은 묶음 표현 때문에 중량을 놓치던 문제도 수정했다.

## 자원과 백필

약 15초마다 과거 글 50건과 이미 연결된 글 최대 25건의 근거를 준비한다. 신규 변경을 우선하고 회차당 최대 50건을 추출한다. 미연결 참조는 최대 30건씩 순환 확인한다. 진행은 `ClassificationState`의 `products:sources:backfill:merchant-identifiers-1`, 추가 연결 누계는 `products:sources:revisit`에 남는다. 요청과 참조는 게시물별로 갱신해 반복 수집으로 행이 계속 늘어나지 않는다.

`0015_product_sources`를 먼저 적용하고 상품 워커를 교체한다. 크롤러는 DB 트리거로 요청을 남기므로 재시작이 필요 없다. 기존 0.15 CPU·192 MiB 제한과 로그 순환 정책을 유지한다. 이전 워커로 되돌릴 때도 새 요청 테이블을 유지할 수 있다.

## 검증

로컬 상품·썸네일 회귀 테스트 120개, 최종 운영 이미지의 백엔드 테스트 54개 통과. 웹 API 검증은 로컬 전체 테스트에 포함하고, 웹 모듈이 없는 운영 워커에서는 `web` 태그를 제외한다.

실제 PostgreSQL의 별도 임시 스키마에서 신규 글·URL/제목 변경·무변경·늦은 응답·ID 조회·동일 상품 연결·가격 보존·단축 링크 캐시 저장/재사용을 확인하고 전체 롤백했다. 운영 데이터에 시험 게시물을 넣지 않는다. 최근 3,000개 게시물 표본에서는 외부 요청 없이 1,723개에서 번호를 확인했다. 이는 번호 추출 범위이며 상품 연결 정확도나 전체 연결 완료 비율이 아니다.
