# 크롤러 서버 CPU 효율화 — 2026-09-20

대상은 `168.107.29.18`의 `instance-20251207-1802`(2 vCPU, 12 GiB)다. 11:27 KST에 운영 반영했다. 변경 전 모델 보호 타이머가 기록한 1시간 CPU 평균은 83.67%, 95백분위는 91.2%였다. 메모리 부족보다 반복적인 브라우저 실행이 주된 병목이었다.

## 원인과 적용 내용

- 아카라이브의 FlareSolverr 미들웨어가 Scrapy 쿠키 미들웨어와 같은 우선순위 700에 등록돼 있었다. 쿠키 헤더가 만들어진 뒤 인증 쿠키를 전달해 일반 HTTP 요청이 반복적으로 403을 받았다. 순서를 650으로 수정했다. 변경 전 한 회차에는 403 응답이 132회 있었다.
- 스파이더·도메인별 브라우저 세션을 재사용한다. HTML과 쿠키를 확보하면 `about:blank`로 이동해 페이지의 타이머·광고 실행을 멈추고, 회차 종료 시 세션을 제거한다. 브라우저가 필요한 요청에는 10분 세션 TTL을 적용한다. 강제 종료 후에는 같은 세션 이름을 회수한다.
- 인증 쿠키가 일반 HTTP에 적용되지 않는 경우 두 번의 차단 후 해당 회차에서는 재사용 브라우저를 쓴다. API 오류·빈 응답은 503으로 기록하고 재시도를 한 번으로 제한한다. `flare/` 통계로 브라우저 사용, HTTP 성공, 정리, 오류를 구분한다.
- 성공 후 대기 시간을 아카라이브 600초, FMKOREA 180초로 조정했다. 뽐뿌 600초, 나머지 60초와 회차별 수집 페이지 범위는 유지한다. 실제 재수집 간격은 실행 시간과 공용 큐 대기를 포함한다.
- 로컬 모델은 호스트 CPU가 80% 이상이면 중지한다. CPU 60% 미만·가용 메모리 4 GiB 이상이 두 번 연속 관측되면 다시 시작한다. 60–80%에서는 현재 상태를 유지해 잦은 재시작을 줄인다. 메모리 3 GiB 미만·학습 실행·작업 없음에 대한 중지 조건도 유지한다.

세션 생성·재사용·삭제는 [FlareSolverr의 공식 세션 API](https://github.com/FlareSolverr/FlareSolverr#sessionscreate)를 사용한다. 운영 이미지의 실제 구현도 함께 확인했다.

- 실행 중인 크롤러 이미지를 기반으로 미들웨어와 아카라이브 우선순위만 변경했다. 아카라이브 파일 전체를 로컬 작업본으로 덮어쓰지 않았다.
- 새 이미지: `crawler-image:efficiency-20260920-r1`, `sha256:ad92e3baafe1420d884fb56513d8fc3b288460fc937ec7ff883873ef9a6f2ce2`. `crawler-image:latest`도 이 이미지를 가리킨다.
- 기존 이미지: `sha256:4d793e1c890da89ec95f3593f52b4edd6fb02b1fa0f48d5d5062d566c47919bd`. 기존 컨테이너는 `crawlers-bot-before-efficiency-20260920` 이름으로 정지 상태 보관했다.
- 기존 Docker 설정 전체를 복제하고 이미지와 두 사이트 대기 환경변수만 변경했다. 크롤러 1 CPU·8 GiB, FlareSolverr 0.75 CPU·1 GiB, 모델 0.20 CPU·3 GiB의 상한, 네트워크·볼륨·로그 제한을 보존했다. 크롤러의 제어된 재시작 구간은 22.51초였다.

## 운영 관찰 시 주의점

CPU의 100%는 2 vCPU 호스트 전체 기준이다. Docker의 CPU 백분율은 코어 한 개 기준이므로 직접 비교하지 않는다. 변경 전후 수집 대상과 시간대가 같지 않아 측정치를 장기 부하 보장이나 요청당 비용의 정확한 감소율로 해석하지 않는다. 짧은 부하 급증은 가능하다.

뽐뿌에는 판매처명 `em` 요소가 없는 게시물에서 `NoneType` 예외가 발생하는 기존 파서 문제가 있다. 이전 컨테이너의 11:14 KST 로그에도 동일한 오류가 있었고, 이번 변경은 뽐뿌 파서를 수정하지 않았다. 실제 갱신이 있더라도 모든 게시물의 완전한 수집을 의미하지 않는다.

## 운영 기록과 복구

서버의 `/root/crawler-efficiency-20260920/`에 `deployment.json`, 변경 전 Docker 설정 `crawler.before.json`, 모델 보호 코드 `guard.before.py`, 검증 JSON을 보관했다. Docker 설정에는 인증정보가 있을 수 있으므로 공개하거나 저장소에 복사하지 않는다.

복구가 필요하면 현재 컨테이너가 위 새 이미지인지 확인한 뒤 정지·제거하고, 보관한 이전 컨테이너 이름을 `crawlers-bot`으로 되돌려 시작한다. `/usr/local/lib/geteverything-categories/guard.py`를 `guard.before.py`로 복구하고 `crawler-image:latest` 태그도 기존 이미지로 돌린다. DB·상품 워커·FlareSolverr 이미지 변경은 없어 별도 데이터 복구가 필요하지 않다.
